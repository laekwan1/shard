## 고침 (빌드 318)
- **[H1] 인증서 폐기 정밀화** — `ensure_certificate`가 발급 실패 시 **포털 거부("developer portal error")일 때만** 폐기. 네트워크/전송 오류엔 폐기 안 함(순간 오류에 폐기하면 다른 기기 앱을 죽임). 특정 코드(7460) 의존 제거 = 316→317 회귀의 뿌리 제거. engine.rs.
- **[H2] 세션 보존** — `resign_and_install_blocking`가 `result.is_err()`면 **무조건** 세션 비우던 것 제거. 설치/서명 실패에도 세션이 지워져 매번 재로그인 → **계정 잠금 패턴**이었다. 세션은 1100(만료)에서만 비운다. engine.rs.
- **[H3] FFI 패닉 방어** — `shard_resign_run/selfupdate/rsd_probe/rsd_install`의 blocking 호출을 `catch_unwind`(guarded)로 감쌈. idevice/plist/zip 파서가 이상한 기기 응답에 패닉→C 경계 넘어 프로세스 abort(설치 중이면 확장 사망)했는데, 이제 에러 JSON 반환. resign_ffi.rs.
- **[H4] 프로브가 배타에 참여** — `rsdProbe`/`minimuxerProbe`/`run`이 `anyResignRunning`을 안 봐 자동 재서명 중 둘째 터널/세션을 열 수 있던 것 → 가드에 추가(단일세션 49152 리셋 방지). Resign.swift.
- **checkForUpdate 고착 제거** — 가드에 `!anyResignRunning` 추가. 수동 재서명 중 `selfUpdateStarted`가 세팅만 되고 bail해 버전 업데이트가 실행 내내 죽던 것 방지. Resign.swift.
- **[M10] 키/인증서 저장 실패 표면화** — 삼키던 `let _ = fs::write` → 실패 시 로그 경고(재발급 루프 진단). engine.rs.
- **디바운스 `.inactive` 배제** — isPlaying 3초 재확인을 `!= .active` → `== .background`. 제어센터·통화 배너(사실상 포그라운드)에서 공연히 재서명 돌던 것 배제. ShardApp.swift.

## 남김 (이유 — 내재적/위험/후속)
- **설치 실패가 `ok:true`로 보고**(rsd.rs:353): 자기덮어쓰기라 **완료신호가 구조상 없음**(installd는 앱 종료 시 반영). Rust가 성공/실패를 구분 못 함 → silent 경로가 24h 쿨다운까지 찍어 재시도를 막을 수 있음. **근본 대응은 "재실행 후 ShardResignStamp 확인"으로 밖에서 판별**. 콜 안에서는 못 고침 — 후속.
- **루트 alert 3개 경쟁으로 '재시작' 팝업 묻힘**(ShardApp.swift): showRestartAlert와 errorText가 동시 참이면 SwiftUI가 하나 드롭 → 재서명 미확정 가능. SwiftUI alert 동작이라 잘못 건드리면 회귀 위험 → 신중히 후속(예: 단일 alert+상태 enum으로 통합).
- **실패 백오프 없음**(H2b): 실패가 반복되면 트리거마다 애플 로그인 재시도. H2(세션 보존)로 재로그인 churn은 크게 줄었으나, 완전한 백오프(실패 타임스탬프)는 트리거 로직 변경이라 회귀 위험 → 후속.
- **`certs.last()` 폴백**(engine.rs): certRequestId≠certificateId로 매칭 실패 시 최신 것 폴백 → 2인증서 계정에서 내 키 아닌 인증서로 서명할 수 있음. ID 매칭 확인이 필요하나 포털 응답 형식 확인 후 → 후속.
- **인증서 미포함 프로파일에 그냥 서명**(engine.rs:248 부근), **App ID 9401 복구 없음**(운영 경로), **verify가 다른 번들ID 테스트** → 초록불이 운영 보증 못 함. **addDevice 미구현**(새 기기 부트스트랩 Sideloadly 의존).
- **BGTask 150초 캡/만료핸들러 없음**·**AFC 180초 vs beginBackgroundTask 30초** 불일치·**저장 계정 없으면 자동 no-op**·**저전력모드 BGTask 억제 미문서화**.
- LOW: connect-then-drop 프로브 export 유지(재도입 footgun) · resultCode 비정수 성공 처리 · Mach-O 슬라이스 패닉(PC 전용) · `notice` 死코드 · 디바운스 취소토큰 없음.

## 설계 영향성 (아키텍처)
1. **무료 Apple ID 구조적 취약**: 인증서 소수 공유·7일 만료·주간 App ID 한도·`available_quantity` 미사용. 평상시엔 `ensure_signing_identity` **재사용**이라 폐기가 안 일어나 두 폰 공존 안정(재서명 한 폰이 다른 폰 안 건드림 — 실측). 폐기는 "재사용 실패 창"(갓 설치·만료·외부폐기)에서만 위험.
2. **단일세션 49152를 Swift에서만 가드** → Rust single-flight 락을 두면 언어 무관 강제(후속 권장).
3. **자기덮어쓰기 설치 완료신호 없음** → ok:true가 거짓일 수 있음 → 성공/실패는 재실행 후 스탬프로 밖에서 판별.
4. **상태기계 복잡도**: 7~8 플래그·3 스코프·3 리셋 규칙. "호출부가 플래그 세팅 후 selfUpdate 호출→가드 bail"이 stuck-flag의 구조적 원인. **"재서명 진행 중?"을 하나의 main-actor 게이트로 통합**하면 이 계열이 대부분 사라짐(후속 권장). "모든 진입점 main actor" 불변식을 코드에 명시할 것.
5. **백그라운드 5단계 중 4개가 확률적**(BGTask 스로틀·저전력 억제·150초 캡·silent은 종료 필요). **확정 보장은 포그라운드 ≤2일 하나뿐** — 코드/문서에 "나머지는 예상된 폴백"으로 명시.
6. **원격 config 평문 HTTP 허용**(config.rs:96) → MITM이 인증 트래픽 리다이렉트 가능. 현재 미사용이라도 켤 때 https 강제 필요.
