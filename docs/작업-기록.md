# 작업 기록

무엇을 만들었는지, **왜 그렇게 만들었는지**, 그리고 무엇을 측정해서 알아냈는지를 남긴다.

결정의 근거를 적는 이유는 하나다. 나중에 같은 자리에서 다시 고민하지 않기 위해서다. "이건 이미 해봤고 안 됐다"를 모르면 같은 길을 두 번 간다.

## 측정해서 알아낸 것

추측이 아니라 실제로 재본 값들이다. 이 표가 여러 결정의 근거다.

### YouTube는 형식별 주소를 더 이상 주지 않는다

- 형식 목록에 적힌 주소로 요청하면 **403**. 스로틀링 파라미터(`n`)를 지워도 403
- 플레이어 코드에 그 파라미터를 고치는 함수가 **더 이상 없다**
- 데스크톱 페이지는 형식 40개 중 **주소가 있는 것이 0개**
- 대체 클라이언트(iOS·VR·TV)는 전부 막힘 — 400 / "봇이 아님을 확인하세요" / 지원 종료

결론: **SABR 프로토콜을 직접 말하는 것 외에 길이 없다.**

### SABR 요청 구조 (라이브 트래픽에서 읽어낸 것)

| 필드 | 의미 |
|---|---|
| 1.f28 | 재생 위치(ms) — **이것이 다음에 받을 구간을 정한다** |
| **2** | **"이미 재생 중인 형식"** |
| 3 | 이미 받은 구간 |
| 5 / 19 | 서버 설정 · 봇 검증 토큰 (불투명, 그대로 복사) |
| 16 / 17 | 음성 · 영상 후보 목록 |

**가장 값비쌌던 발견**: 필드 2에 받고 싶은 형식을 적으면 서버가 "이미 갖고 있다"고 판단해 **파일 앞 265바이트(초기화 세그먼트)를 안 보낸다.** 그러면 모든 프레임이 들어있어도 열리지 않는 파일이 된다. 필드 2에는 **다른 형식**을 적어야 한다.

효과 없던 것도 적어둔다: `ClientAbrState`의 f23·f36·f39를 바꿔도 응답이 한 바이트도 안 바뀐다. 트랙 종류 비트필드(f34)도 마찬가지다. **서버가 무시한다.**

### 음성만 받을 때

필드 17(영상 목록)을 빼면 영상이 **50.6MB → 0.39MB**. 서버가 가장 작은 걸 딸려 보낸다. **0으로 만드는 방법은 찾지 못했다.**

### 코덱별 용량 (1080p60 기준)

| 코덱 | 용량 | H.264 대비 |
|---|---|---|
| AV1 | 119 MB | 2.1배 작음 |
| VP9 | 161 MB | 1.5배 작음 |
| H.264 | 246 MB | 기준 |

### 회선 측정 (모바일)

- 영상 하나: 3~5 MB/s
- 영상 둘 동시: 합쳐서 5~7 MB/s

→ **두 배로 늘려 1.4배.** 병렬화의 이득이 작다.

## 하지 않기로 한 것과 그 이유

**병렬 다운로드.** 위 측정대로 1.4배를 얻는 대신 요청 수가 3~4배가 되어 봇 탐지 위험이 커지고, 스레드·파일 공유·완주 판정을 다시 짜야 한다. 회선이 병목일 때 실제로 빠른 길은 **덜 받는 것**이고, AV1을 고르면 2.1배를 위험 없이 얻는다.

**PO Token 생성 엔진.** YouTube의 검증 코드는 환경을 적극 검사하고 검사 항목을 수시로 바꾼다. 흉내내면 더 많은 일을 해서 더 잘 깨지는 것을 얻는다. 지금은 브라우저가 만든 토큰을 빌려 쓴다 — 그게 정답이다. **브라우저 없이 받아야 할 때(명령줄·서버)만 다시 검토한다.**

**PC를 브라우저 기반으로 대체.** PC Shard의 가치는 크롬이든 게임이든 전부 우회된다는 점이다. 브라우저 기반으로 바꾸면 그게 사라진다. 브라우저 창은 다운로드용으로 **추가**된 것이지 대체가 아니다.

---

## 되풀이하지 말아야 할 실수

**같은 코드가 페이지에 따라 다르게 동작한다.** 모바일 YouTube와 데스크톱 YouTube가 주는 정보가 다르다.

- 데스크톱은 `contentLength`를 **주지 않는다** → 용량을 필수 조건으로 쓰면 안 된다
- 데스크톱은 음성 트랙 **전부에** `xtags`를 붙인다 → "태그 없는 것만"은 조건이 아니라 선호여야 한다

→ **페이지에서 읽는 값에 조건을 걸 때는 없을 수도 있다고 가정한다.**

**진단은 코드가 실제로 쓰는 값을 보여줘야 한다.** "음성 20개"라고 표시했는데 그건 필터 이전 개수였다. 그래서 음성이 살아있다고 착각해 엉뚱한 곳을 고쳤다.

**두 가지 질문을 한 덩어리로 다루지 않는다.** 음성 선택에서 *어느 언어*와 *어느 음질*을 뭉뚱그렸다가, 더빙된 영상에서 한국어 시청자에게 영어가 나왔다. 언어를 먼저 정하고 그 안에서 음질을 고른다.

**창이 어떻게 겹쳐 그려지는지 확인하지 않고 결론부터 내지 않는다.** UI 작업에서 세 번 헛짚었다 — 창을 잘라내면 자식 창도 둥글어질 것이라는 짐작(자식은 자기 모서리를 유지한다), 주소창이 z-순서 문제일 것이라는 짐작(WebView2는 합성 표면이라 자식 창으로는 안 올라간다), 마우스가 밴드를 벗어나면 숨겨야 한다는 짐작(팝업으로 가는 길이 페이지 위였다).

## 구조

### PC Shard

```
crates/shard/src/
  engine.rs         패킷 가로채기와 판단
  desync.rs         분할·디코이
  parse/
    tls.rs          ClientHello에서 호스트명
    quic_initial.rs QUIC 첫 패킷 복호화 → 호스트명
  download/
    sabr.rs         YouTube 요청 조립·응답 해석
    pull.rs         다운로드 대화 루프
    youtube.rs      페이지 응답 해석 + 주입 스크립트
    mp4.rs / webm.rs  받은 스트림에서 프레임 추출
    mkv.rs / ebml.rs  Matroska 작성
    save.rs         위 조각들을 이어 파일 하나로
    browser.rs      WebView2 창 (직접 그린 프레임, 탭, 주소창 팝업)
```

**설계 원칙 하나**: 네트워크가 필요한 부분은 클로저로 받는다(`pull.rs`). 그래서 산술이 들어간 부분을 실제 서버 없이 시험할 수 있다. 모바일에서 겪은 두 버그가 여기서는 회귀 테스트로 박혀 있다.

### 모바일

Kotlin. 프로토콜이 Rust와 **중복**되어 있다. 합칠 수 있지만(안드로이드가 이미 JNI로 Rust를 부른다) 지금은 두지 않았다 — 깨졌을 때 실제 작업은 "살아있는 요청에서 필드 번호를 다시 읽는 것"이고 그건 한 번만 한다. 알아낸 걸 두 곳에 적는 건 그 위에 얹히는 작은 일이다.

## 브라우저 창을 닫으면 프로그램이 통째로 죽던 문제 (2026-08-09)

**증상** — 브라우저 창을 닫으면 on/off 창도 같이 닫히고 트레이 아이콘도 사라졌다.

**틀린 가정** — 종료 경로를 의심해서 `quitting` 플래그와 트레이 메뉴 매칭을 여러 번 읽었다.
로그에는 아무 흔적도 없었는데, 그게 단서였다. 정상 종료라면 로그가 남는다.

**실제 원인** — Windows 이벤트 뷰어(응용 프로그램 로그)에 매번 기록되고 있었다.

    오류 있는 모듈: EmbeddedBrowserWebView.dll
    예외 코드: 0xc000041d
    오류 오프셋: 0x399a59   (매번 동일)

`0xc000041d`는 콜백 밖으로 예외가 빠져나갔을 때 프로세스를 즉시 죽이는 코드다.
정리 순서가 뒤집혀 있었다:

    WM_CLOSE   → DestroyWindow(hwnd)   창과 자식(WebView2의 창까지) 파괴
    WM_DESTROY → PostQuitMessage(0)
    스레드 종료 → 그제서야 VIEWS의 WebView가 drop

WebView2는 호스트 창이 살아 있는 동안 컨트롤러가 닫혀야 한다.

**고친 것** — `WM_CLOSE`에서 `VIEWS`를 먼저 비우고 주소창 팝업을 닫은 뒤에 창을 파괴한다.
`Command::Close`도 `PostQuitMessage` 대신 `WM_CLOSE`를 보내서 이 순서를 한 곳에만 둔다.

**남길 교훈** — 프로세스가 로그 없이 사라지면 종료가 아니라 크래시다.
Rust 로그가 아니라 Windows 이벤트 로그를 먼저 본다:

    Get-WinEvent -FilterHashtable @{LogName='Application'} | Where-Object { $_.Message -match 'shard' }

## Veil 서버 주소 고정 — DuckDNS + 예약 IP (2026-08-10)

**문제** — 링크에 서버 IP를 박아두면 오라클 임시 IP가 바뀔 때 폰이 엉뚱한 곳을 가리킨다. 실제로 한 번 겪었다(잃어버린 줄 알았던 SSH 키는 `ssh-key-REDACTED`가 진짜였고, 이름이 `2026-08-06(Veil)`인 키가 다른 것이었다).

**해결 — 두 겹**
1. `scripts/setup-duckdns.sh` — 서버에 systemd 타이머 설치. 5분마다 공인 IP를 확인하되 **바뀌었을 때만** DuckDNS에 알린다(하루 한 번은 무조건, 이름 만료 방지). 공인 IP는 오라클 메타데이터에서 먼저 시도하고, 없으면 외부 확인 서비스로 대체한다 — 이 인스턴스는 메타데이터에 publicIp가 없어서 외부 확인을 탄다. 토큰은 명령줄로 받지 않고 숨김 입력.
2. `scripts/reserve-oracle-ip.sh` — 안내용. 실제로는 OCI CLI로 직접 처리했다.

**중요 — 제자리 승격은 이제 불가능하다.** `oci network public-ip update`에 `--lifetime` 옵션이 없어졌다. 예약 IP는 **새로 만들어 붙이는 수밖에** 없고, 그 과정에서 공인 IP가 한 번 바뀐다. 순서: 예약 IP를 연결 없이 먼저 생성 → 임시 IP 삭제 → 예약 IP 연결(사설 IP에 이미 임시 IP가 붙어 있으면 409 충돌, 그래서 삭제가 먼저).

**결과** — `<서브도메인>.duckdns.org` → `<예약 IP>`(RESERVED). IP를 바꾸자 DuckDNS 스크립트가 스스로 감지해 갱신하는 것을 로그로 확인했다. 링크의 IP를 도메인으로 바꾸면 폰은 자동으로 따라간다.

## 보관함 이어재생·무작위 재생 (2026-08-10)

`MediaPlayer` 완료 콜백에서 다음 영상으로 넘어간다. 설정 대화상자에 토글 두 개 추가(다음 영상 이어 재생 / 폴더 내 무작위 재생). 둘 중 하나라도 켜지면 `advance()`가 돈다.

- 목록은 매번 `shown()`으로 새로 읽고, 현재 항목은 **위치가 아니라 id로** 찾는다(4초마다 목록이 갱신돼 인덱스가 밀릴 수 있으므로).
- 무작위는 현재 폴더 필터 안에서, 자기 자신을 제외하고 뽑는다. 순차는 끝에 닿으면 반복하지 않고 멈춘다(주머니 속 폰이 라이브러리를 두 번 돌지 않게).
- 백그라운드 진행은 전경 서비스가 프로세스를 살려두기에 완료 콜백이 계속 뜬다.
