## 바로 이어서 할 것 — 폰 화면 구조 개편

폰 앱을 PC판과 같은 구조로 맞추는 일이다. 다섯 항목이 서로 얽혀 있으니
**순서대로** 한다. 각 항목마다 에뮬레이터로 확인하고 넘어간다.

### 1. 홈 화면

앱을 열면 PC처럼 **전원 버튼 화면**이 먼저 나온다. 지금은 브라우저가 첫
화면이다. 상단에서 보관함·브라우저로 간다.

### 2. 주소창

좌상단 핸들(`handleArea`)을 누르면 뜨는 패널을 **PC의 제목표시줄 + 주소창**
모양으로. 지금 그 자리에 뜨는 것을 그대로 활용한다.

### 3. 재생바 — PC 것을 차용

`view_library.xml`의 `nowPlaying`과 전체화면 컨트롤을 다시 짠다.

- **백그라운드 재생 · 다음 재생 · 무작위**를 재생바 안으로 (지금은 `librarySettings` ⋮ 안의 대화상자)
- **전체화면 축소 버튼**도 재생바 안으로 (지금은 우하단에 따로 떠 있음)
- 전체화면의 좌상단 뒤로가기·우하단 축소는 **재생바처럼 눌러야 뜨고 아니면 사라지게**

### 4. 음악 재생 화면에 커버

파일에 박힌 커버를 재생 화면에 띄운다. 읽는 코드는 이미 있다 —
`LibraryScreen.embeddedArt()` (`MediaMetadataRetriever.embeddedPicture`).
PC는 16:9 자리에 잘리지 않게 통째로 놓는다.

### 5. 새폴더 옆 ⋮ 제거

**3번이 끝난 뒤에.** 그 버튼이 재생 설정으로 가는 유일한 길이라, 먼저 지우면
기능이 잠긴다(한 번 그렇게 깨뜨렸다).

## 그 다음

**Veil 속도 개선.** 손댈 곳은 짐작이 가지만(전송 계층, 혼잡 제어, 서버 위치,
다중 연결) **먼저 무엇이 느린지 재는 것**이 순서다. 왕복 시간인지, 암호화
처리인지, 연결 수립인지에 따라 답이 완전히 달라진다.

**폰 차단 검사.** 폰 엔진은 소켓 수단으로 우회하므로 전략 목록이 PC와 다르고,
결과를 Kotlin으로 넘길 C ABI도 없다. 폰용으로 다시 짜야 한다.
— 다만 **폰의 우회는 Veil에 맡기기로 했으므로 우선순위는 낮다.**

**옛 UI 정리.** `crates/shard/src/ui.rs`(창 두 개짜리)는 이제 고유 기능이 없다.
당분간 남겨 두되 새 기능은 넣지 않는다.

## 이번에 끝난 것 (요약)

**PC** — 창 통합 마무리. 보관함(선반·폴더·순서 변경·썸네일·커버), 재생기(하단
띠·이전/다음·속도·시크·순서대로/무작위·위치 저장), 설정(초기화·로그 보기·차단
검사), 창(중앙 배치·가장자리 조절·트레이 더블클릭).

**저장 품질** — 프레임을 디코딩 순서로 쓰고 보여줄 시각을 적는다(B프레임 문제),
파일 앞에 탐색 색인, 음악 커버를 파일 헤더 안에.

**네트워크** — `0.0.0.0`은 주소가 아니다: 프로브는 다른 답으로 넘어가고,
전달기는 다음 상위 서버로 넘어간다.

**폰** — 커버를 파일 안에, 재생 위치는 손으로, 목록 순서 끌어서 바꾸기, 중복
다운로드 경고, 상태바 겹침 수정, 헤더에서 제목 빼고 스위치를 최상단으로,
행 메뉴는 이름 바꾸기·삭제만.
