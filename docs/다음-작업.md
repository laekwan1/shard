  accent(청록 #2DD4BF)로 통일. 에뮬레이터에서 전부 확인.
- **그밖(끝)**: PC 뒤로/앞으로 비활성 표시(add_HistoryChanged, 쇼츠 pushState 포함),
  skipAds 3플랫폼 파리티, 배터리 폴링을 document.hidden에 게이트, 안드로이드 썸네일
  일관(FIT_CENTER)·닫기 흰 X.

  파일 앞 ID3v2.4 APIC. **desktop 전용**(symphonia·mp3lame를 desktop 기능에만 걸어
  폰 빌드 미포함). Opus(.weba)는 디코더가 더 필요해 그대로, 변환 실패 시 .m4a 폴백.
  ffmpeg 단편 AAC로 저장 경로와 동일 디먹싱→변환 검증: mp3/48k/스테레오/320k/3.05초,

## iOS 다운로더 (2026-08-21, 진행 중)

우회는 빼고 **영상 받기 위주**. 배경·결정은 [iOS-가능성.md](iOS-가능성.md).
맥은 **GitHub Actions macOS 러너(무료 클라우드 맥)**로 빌드하고, 기기 설치는
**SideStore(사이드로더, 맥 불필요)**로 한다. 유료 전용 맥·개발자계정 없이 간다.

끝난 단계 (전부 러너 CI로 검증됨):

1. **다운로드 엔진 분리** — `save`를 `desktop`이 아닌 새 `download` 기능으로
   빼서 폰이 쓴다(reqwest+std::fs만, WebView2 없음). desktop이 download를 포함.
   reqwest 암호 백엔드는 **ring**으로 통일했다 — aws-lc-rs는 iOS cdylib에
   링크되지 않는다(`ld: symbol(s) not found for arm64`). `save::use_ring()`가
   ring을 프로세스 프로바이더로 한 번 설치.
2. **모바일 C ABI** — `crates/shard-mobile/src/download.rs`:
   `shard_download_hls`/`shard_download_direct`. URL·referer·저장폴더·제목을
   받아 받기+먹싱, 진행/취소는 C 함수포인터. 결과 `{ok,path|error}` JSON.
3. **Swift 앱 셸** — `ios/Shard/`. 브라우저(WKWebView+주소창)·보관함(AVPlayer)
   두 탭. `Capture.js`를 문서시작 주입해 fetch/XHR 후킹+DOM 스윕으로 `.m3u8`·
   영상파일 URL 포착(iOS엔 shouldInterceptRequest가 없다). 잡힌 URL을 C ABI로
   넘겨 Documents(=Files 앱)에 저장.
4. **빌드/배포 CI** — `ios/scripts/build-xcframework.sh`(기기+시뮬 staticlib→
   xcframework), `ios/project.yml`(XcodeGen, .pbxproj 손대지 않음),
   `.github/workflows/ios-app.yml`. 시뮬레이터 컴파일 게이트 + **실기기 무서명
   `.ipa`를 아티팩트 `Shard-unsigned-ipa`로 업로드**. SideStore가 기기에서
   사용자 Apple ID로 서명하므로 인증서는 CI에 넣지 않는다.
   - 시뮬 빌드는 러너(Apple Silicon)에서 `ARCHS=arm64`로 고정해야 한다 —
     Release 기본이 x86_64까지 요구하는데 우리 sim 라이브러리는 arm64 전용.

5. **MP4 출력(끝남)** — iOS AVPlayer·WKWebView가 mkv/webm를 재생 못 해 받은
   파일이 안 열리던 문제. TS는 늘 H.264+AAC라 MP4가 맞으므로 새 `mp4mux` 모듈로
   비단편 MP4를 쓴다(B프레임 ctts, 오디오 정확 타임스케일). `remux_ts`가 mkv
   대신 이걸 쓰고 확장자 .mp4 — 데스크톱도 함께. ffmpeg로 만든 실제 TS를 변환해
   ffprobe 정상 인식·75프레임 전부 디코딩으로 검증(examples/ts2mp4.rs).

6. **유튜브 SABR(끝남)** — 데스크톱 캡처를 이식. `Capture.js`(문서시작)가
   videoplayback POST(SABR 요청)를 잡고, `Ask.js`가 다운로드 시 실행돼 offer JSON을
   반환(데스크톱 ASK를 evaluateJavaScript용으로 개작). `save::youtube_qualities`/
   `run_youtube`(desktop 전용 downloads.rs Job 로직을 download 기능으로 옮김) +
   C ABI `shard_youtube_qualities`/`shard_download_youtube`. 화질 선택 시트.
7. **VLCKit 내장(끝남)** — MobileVLCKit을 CocoaPods로. 보관함을 libVLC로 재생 →
   유튜브 webm(VP9/Opus)·mkv까지 앱에서 재생. CI는 xcodegen→pod install→workspace.
   음악은 이제 Opus(webm)로 추출(AAC보다 작고 좋음).
8. **UI 파리티(끝남)** — 3탭(브라우저/다운로드/보관함). 동시 다운로드(DownloadsStore,
   진행률·취소), 보관함 폴더(생성/이동/이름/삭제)·썸네일+길이 배지(MediaProbe=
   VLCMediaThumbnailer), 플레이어(이전다음·속도·위치기억·백그라운드오디오·우2배속/
   좌되감기 홀드), 웹 영상 꾹 눌러 다운로드, 웹 영상 인라인 강제.

9. **안드로이드 파리티 라운드(끝남 대부분)** — 창모드 스테이지(즉시 전체화면
   아님)+확대, 제스처(탭/더블탭±3초 좌우1/3/가운데토글, 길게 2배속·되감기,
   전체화면 밝기/소리 세로드래그+게이지, 스와이프 상하 전체화면·좌 정지·우 웹으로,
   핀치줌), 하단 이전/다음 트랙·음소거·컨트롤 자동숨김, 주소창 제스처화(엣지
   스와이프)·당겨새로고침, 비디오/음악 스와이프 전환, 폴더(집아이콘=저장소, 드래그

## 사용자 검증 대기 (이 환경에서 확인 불가)

아래는 코드/단위테스트는 통과했으나 **실제 실행 검증은 사용자 몫**이다 — 헤드리스
환경이라 실제 사이트 다운로드·UAC·탐색기 파일연결을 여기서 돌려볼 수 없다.

- **PC HLS 다운로드**: 직접 mp4 · fMP4 · **MPEG-TS(.ts) 디먹싱**까지. `ts.rs`가
  PAT/PMT/PES/Annex-B/ADTS를 풀어 mkv로 담는다. 파서는 단위테스트로 지켰다.
  대상 사이트에서 실제로 받아지는지 확인 필요.
- **파일 기본 연결 + asInvoker**: 매니페스트를 asInvoker로 바꿔 평소 UAC 없이
  뜬다. 엔진 ON시 `--engine`로 승격 재실행(claim 넘김/되찾기). 미디어 더블클릭 →
  실행 중이면 WM_COPYDATA로 넘겨 `/external` 재생, 아니면 새로 떠서 재생.
  HKCU에 ProgID 등록. **기본값 설정은 사용자가 '연결 프로그램'에서.**

**PC 다운로드가 xvideos·pornhub에서 빈 목록.** 감지가 전적으로 YouTube 전용이다
— `ytInitialPlayerResponse.streamingData`만 읽는다(`download/youtube.rs:382`).
이 사이트들은 HLS(.m3u8)를 MSE/blob로 재생하므로 `streamingData`가 없어 빈
목록이 된다. RECORDER(`youtube.rs:296`)도 `videoplayback`만 잡는다. **고치려면**
HLS 파이프라인이 필요하다 — .m3u8 파싱, 세그먼트 받기, TS→MP4. 폰에는 `Hls.kt`가
있으나 PC(Rust)에는 없다. 큰 작업이라 착수 전 사용자 확정.

**PC 미디어 파일 기본 연결.** 영상·음악을 더블클릭하면 Shard 재생 모듈이 뜨게 —
가능하다. 레지스트리 ProgID·확장자 연결 + `main.rs`가 파일 경로 인자를 받아
보관함 재생으로 바로 들어가는 길 + 이미 실행 중이면 실행 중 사본에 경로를
넘기는 처리(WM_COPYDATA 등, 트레이 깨우기와 같은 결). 중간 규모. 사용자 확정 후.

미끄러져 나온다. 한 번 누르면 고르고(picked), 두 번 누르면 재생한다. 스테이지
안에 넣어 전체화면에서도 뜬다. 손잡이·패널의 눌림과 휠은 뒤에 깔린 길게누르기·
소리 조절로 새지 않게 `stopPropagation`으로 막았다. `assets/ui/`의 세 파일.

**PC 재생바 개편** — 닫기 없앰, 소리 항상 보임, 순서대로·무작위를 소리 왼쪽,
재생시간을 다음 오른쪽. 휠로 소리, Enter/더블클릭으로 전체화면, 화면 좌우 길게
누르기(오른쪽 2배속·왼쪽 되감기), 소리 기억. (앞 세션에서 시작, 이번에 큐까지.)

**PC 트레이 재실행** — 이미 실행 중일 때 실행파일을 다시 열면 팝업 대신 창이
앞으로 온다. 두 번째 사본이 `RegisterWindowMessageW`로 만든 메시지를 브로드캐스트
하고, 첫 사본의 wndproc이 받아 창을 보인다. `uikit/src/single.rs`(`wake_message`,
`wake_the_running_copy`), `shell.rs` wndproc 맨 앞. Veil은 아직 이 메시지를 받지
않으므로 옛 `point_at_the_running_copy`(메시지 상자)를 남겨 둔다.

**폰 재생기 — 길게누르기.** 화면 오른쪽 길게 누르면 2배속, 왼쪽 길게 누르면
되감기(50ms마다 0.2초). `GestureDetector.onLongPress`가 시작하고, 손이 떨어지는
`ACTION_UP`을 터치 리스너가 잡아 끝낸다(디텍터는 뗌을 알리지 않는다). 되감기는
전체화면 좌우 밝기·소리 드래그와 겹치지 않는다 — 길게누르기는 멈춘 손가락으로
시작하고 드래그는 아니므로. `LibraryScreen.kt`.

**폰 브라우저 — 화면 회전.** 주소줄에 회전 버튼(`ic_rotate`). 센서 자동회전은
손이 흔들릴 때마다 돌아 고정할 수 없으므로, 지금 방향에서 세로↔가로를 오가는
스위치로 만들었다. `BrowserActivity.rotateScreen()`. 전체화면 자동 가로는 이미
`applyOrientation()`에 있어 그대로 둔다.

**배포** — PC `shard.exe`(15MB)와 서명된 안드로이드 릴리스(6MB, R8) 모두
갱신해 `release/`에 복사. 에뮬레이터에서 회전 버튼 동작 확인(가로↔세로).
