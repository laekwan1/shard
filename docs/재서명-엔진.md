# iOS 자체 서명 엔진 — 설계 (진행 중)

Shard가 **SideStore 없이 자기 자신(과 Veil)을 재서명**한다. 처음엔 Sideloadly로 1회
설치하고, 이후엔 이 엔진이 갱신한다. **repo는 private 유지**. **개인 사용만** 하므로
GPL/AGPL 소스 제공 의무가 발동 안 함 → **SideStore의 검증된 Rust 부품을 그대로 포팅**한다
(아래 라이선스·포팅 지도 참조). 예전 초안의 "AGPL 참조 금지"는 **철회**됨.

목표는 SideStore 전체가 아니라 **"서명 + 인증 + 설치 갱신" 코어 4조각**만 가볍게 넣는 것.

## 라이선스 (결정 기록 — 개인 사용이라 사실상 무제한)
- Shard 워크스페이스는 이미 **GPL-3.0**. SideStore는 **AGPLv3** — GPLv3와 **호환**.
- 무엇보다 **개인 사용만**(배포 안 함) → GPL/AGPL의 **소스 제공 의무가 발동 안 함**. 즉
  **SideStore의 AGPL Rust 코어를 자유롭게 포팅**해도 된다. (혹시 나중에 배포하게 되면 그때
  소스 제공을 챙기면 되고, 그래도 GPL/AGPL 호환이라 합법.)
- 그래서 **③④는 재구현이 아니라 SideStore의 검증된 Rust를 포팅**한다 — 수 주 절약 + 안정성.
- **LocalDevVPN은 못 없앤다**(설치 터널 엔타이틀먼트는 무료 사이드로드 앱이 못 가짐).
  → 최종 앱 구성 = **Shard + LocalDevVPN**(SideStore 제거, 추가 앱 1개).
- 애플 강제 한계는 그대로: **7일 만료**, 만료된 앱은 자가 실행 불가(부트스트랩).

## 4개 부품과 재료 (③④는 SideStore 포팅으로 확정)

| # | 부품 | 무엇 | 재료 |
|---|---|---|---|
| ① | **서명** | .ipa를 인증서+프로파일로 서명 | **`apple-codesign`(Apache/MPL, 순수 Rust)** — 실제 Shard.app 재서명·검증 완료(PC). 그대로 |
| ② | **Developer API** | 인증서·App ID·프로파일 발급/갱신 | **우리가 직접 구현**(apple-dev-apis는 스텁; AltSign 참조). ③ 세션 토큰·anisette 실어 HTTP |
| ③ | **anisette+로그인** | Apple ID 인증 토큰 | **`omnisette`+`icloud-auth` 포팅**. 애플이 자주 깨는 부분 = 유지보수 핵심 |
| ④ | **설치/갱신** | 프로파일은 `misagent`(㉮ 무중단), 앱은 `installation_proxy`(㉯) | **`idevice` 포팅**(="minimuxer 포팅"의 실질). LocalDevVPN 터널 + 페어링 파일 경유 |

④는 **LocalDevVPN 터널 + 페어링 파일**을 경유해 폰의 lockdownd에 닿는다.

## 포팅 지도 (실제 저장소·소스로 확인 — 착수 중)
각 항목은 저장소를 직접 열어 확인했다(추측 아님). **핵심 정정: ②는 포팅할 Rust가 없다(스텁).**

| 부품 | 원천 | 상태 (실측) |
|---|---|---|
| ① 서명 | `apple-codesign` (직접 의존) | ✅ 실제 Shard.app 재서명·검증 완료. SideStore도 같은 크레이트 |
| ② Developer API | **우리가 직접 구현** (Dadoum/Sideloader `developersession.d` 포팅) | 🔨 **구현·컴파일 확인**(`dev_api.rs`): list_teams/list_certificates/submit_csr/list_app_ids/add_app_id/download_profile + 전송층. apple-dev-apis 스텁 안 씀 |
| ③ anisette+로그인 | `icloud_auth`+`omnisette` 의존 + 전송층 자작 | 🔨 **구현·컴파일 확인**(`auth.rs`): 로그인/anisette는 크레이트, **Xcode GS 토큰**은 get_app_token의 복호 todo를 우리가 완성(AES-GCM), 포털 인증 POST |
| ④ 설치/갱신 | `jkcoxson/idevice` → `installation_proxy`(㉯)+`misagent`(㉮)+`lockdown`/`afc` | 미착수. 다음 증분 |

- **정정**: 앞서 "②③이 한 저장소라 함께 포팅하면 끝"이라 적었으나, 열어 보니 **③만 실제 구현**이고
  **②(`apple-dev-apis`)는 스텁**이다. 그래서 ③은 크레이트 의존, **②는 우리가 HTTP로 직접 구현**한다
  (`developerservices2.apple.com`에 ③ 세션 토큰+anisette 실어 plist POST; 형식은 AltSign 참조).
  ②는 오히려 "포팅"이 아니라 "구현"이지만, 흔한 통념과 달리 **가장 어려운 ③(인증)이 이미 돼 있어**
  전체 실현성은 더 좋아졌다.
- ④의 Rust 코어는 **`idevice`**. (옛 Rust minimuxer는 `rusty_libimobiledevice` 기반이라 deprecated;
  현행 minimuxer(Swift)도 `idevice` 위에 얹힘 → `idevice` 직접 포팅이 현행·능동유지 코어.)
- **의존 방식(당장은)**: `icloud_auth`/`omnisette`를 git rev 고정으로 의존(재현성). "필요한 부분만
  빼서 가볍게"는 폰에서 동작 확인한 **뒤** 트림(동작 전 최적화 금지). 개인 사용이라 라이선스 무관.
- **iOS 연결**: 엔진은 `crates/resign`(lib)에 두고, C ABI는 `shard-mobile`에 feature로 얹어
  `build-xcframework.sh`로 빌드(shard→shard-mobile와 같은 길). **CI(macOS)가 iOS 빌드, 폰이 실증** —
  Shard 개발과 동일 루프(사용자 확정).

## "재서명"의 두 갈래 — 흔한 쪽은 재설치가 아니다 (AltStore 소스로 확인)
처음엔 "재서명=재설치"로 적었는데 **틀렸다**. AltStore `RefreshAppOperation.swift`를 직접 읽어
확인: 평상시 갱신은 앱을 다시 깔지 않는다.

- **㉮ 프로파일만 갱신 (흔한 7일 주기, 재설치 아님).** 7일마다 만료되는 건 앱 바이너리가 아니라
  **프로비저닝 프로파일**이다. 새 프로파일 하나만 발급받아 기기의 `misagent`(lockdown 서비스)에
  심으면 앱은 그대로 계속 열린다. AltStore refresh 경로가 `InstallProvisioningProfilesRequest`를
  보내고 **앱 번들은 손대지 않음**을 소스로 확인. → **무중단·빠름·데이터 그대로.**
- **㉯ 전체 재서명 + 재설치 (드묾).** 서명 **인증서**가 만료/폐기됐거나, 새 빌드거나, 첫 설치일
  때만. 번들을 다시 서명해서 `installation_proxy`로 재설치 — 같은 번들ID라 **업그레이드 설치 =
  앱 데이터 보존**(초기화 아님). 실행 중 인스턴스는 이때 종료될 수 있다.

**추론(실기기로 확인 필요):** ㉮가 성립하려면 무료계정 **인증서**가 7일 프로파일보다 오래 살아야
한다 — AltStore가 프로파일-only refresh를 상시 keep-alive로 쓰는 사실이 이를 뒷받침한다(인증서가
매 7일 죽으면 그 경로가 무의미). 다음 세션에서 실기기로 실측 확인.

**설계 함의:** 모래시계 자동 트리거는 **먼저 ㉮(프로파일만, 무중단)** 를 시도하고, 인증서가 죽어
서명이 깨졌을 때만 **㉯(전체 재설치)** 로 폴백한다. 그래서 ④에는 경로가 둘 필요하다 —
`misagent`(프로파일 설치)와 `installation_proxy`(앱 설치). 둘 다 `idevice` 크레이트가 제공(포팅 지도 참조).

## 죽은 앱은 스스로 못 되살린다 — 부트스트랩 한계 (엔진은 예방적으로만 작동)
**다음에 누가 "실행 시 재인증"을 또 시도하지 않도록 못박아 둔다.**
- **만료되면 실행 자체가 안 된다.** iOS는 실행 직전 `amfid`가 서명·프로파일을 검사하고, 프로파일
  만료든 인증서 만료/폐기든 무효면 앱을 아예 안 띄운다("확인할 수 없음"). 인증서가 죽으면 서명이
  무효 → 실행 불가.
- **"실행하면서 재인증"은 불가능.** 재서명 엔진은 Shard *안의* 코드다. 앱이 안 뜨면 그 코드도 못
  돈다. iOS가 실행 전에 막으므로 앱이 개입할 틈이 **원천적으로 없다** → **죽은 앱은 스스로 못
  살아난다.** SideStore도 동일(SideStore가 만료되면 SideStore로 못 살림, PC 필요). 엔진을 별도
  헬퍼 앱에 빼도 그 헬퍼가 또 7일 만료 — 무한 반복이라 회피 불가.
- **결론: 엔진은 예방적으로만 유효.** 만료 *전에*(3일 이내 자동) 갱신해 앱이 안 죽게 유지하는 것이
  유일한 실질 해법. 앱이 살아있는 동안이면:
  - 인증서 유효 → ㉮ 프로파일만 갱신(무중단, PC 불필요).
  - 인증서 만료 → ㉯ 새 인증서 받아 재서명+재설치(폰에서, PC 불필요) — 단 **앱이 아직 살아있어야.**
- **완전 방전(수 주 방치로 앱 사망) → 외부 부트스트랩 필요**: 최초 Sideloadly(PC) 설치와 같은
  경로로 1회 재설치. **최초 설치를 Sideloadly로 두는 설계가 이 복구 경로도 겸한다.**

## 재서명 타이밍 (사용자 확정)
- **매 실행마다는 안 함**(불필요한 네트워크·발급 낭비). ㉮ 프로파일 갱신은 가볍지만 애플의
  주당 App ID 10개 한도가 있어 아껴 쓴다.
- **포그라운드/백그라운드 둘 다**에서 프로파일(및 인증서) 만료를 확인하고,
  **만료 3일 이내면 자동 갱신**(사용자 확정, 2일→3일). 우선 ㉮ 프로파일만, 필요 시 ㉯ 재설치.
  - 포그라운드 진입(콜드 실행 + 돌아올 때마다) → "안 끄고 계속 사용"도 커버.
  - 백그라운드는 **BGTaskScheduler**로 시도 — 단 iOS 백그라운드 실행은 보장이 없어
    **best-effort**(SideStore 자체 백그라운드 갱신도 자주 실패). 그래서 포그라운드 확인이 주,
    백그라운드가 보조.
- **UI — 주소창 오른쪽 모래시계**: 남은 기간 표시, **탭 = 수동 재서명**. 모래시계는 주소창에서
  **한 번 더 오른쪽 스와이프**해 **우회 on/off 토글이 뜰 때 함께** 노출한다(별도 상시 노출 아님).
- **설정**: Apple ID(+앱 암호) 저장. 없으면 모래시계 탭 시 "계정 저장·재서명 안 됨" 알림.
- 자동/수동 **둘 다** 둔다(택일 아님).

## 단계 (PoC → 확장)
1. ✅ **① 서명 (검증 완료)**: `crates/resign`가 실제 `release/ios/Shard-unsigned.ipa`를 풀어
   `Shard.app`을 재서명하고(메인 `net.sw.shard` + 중첩 프레임워크 `org.videolan.mobilevlckit`),
   다시 읽어 검증 — 각 Mach-O에 `LC_CODE_SIGNATURE`+CMS 암호서명, `_CodeSignature/CodeResources`
   생성 확인(미서명 71→서명 72 로드커맨드). self-signed라 *설치*는 못 하지만(②가 대체) **서명
   파이프라인은 확증**. `default-features=false`로 AWS/App Store Connect 스택도 제거(공증 불필요)
   — 트림 후에도 ① 동작 확인. 남은 것: ②가 준 애플 인증서·프로파일 주입(엔티틀먼트/
   `embedded.mobileprovision`) + iOS 타깃(aarch64-apple-ios) 빌드 — 둘 다 ②/실기기와 맞물림.
2. 🔨 **③ 로그인+anisette (구현·컴파일)**: `auth.rs`가 `icloud_auth`/`omnisette`를 감싸고, **Xcode GS
   토큰**까지 완성(get_app_token의 AES-GCM 복호 todo를 우리가 마저). 다음: 콜백형 `login`을
   `login_email_pass`+`verify_2fa` 단계머신으로 바꿔 폰 2FA UI에 붙임.
3. 🔨 **② Developer API (구현·컴파일)**: `dev_api.rs`에 6개 연산 + `Transport`(포털 인증 POST).
   Dadoum/Sideloader 포팅. **폰에서 왕복 실증** 필요(토큰/헤더/plist 미세형식).
4. 🔨 **⑤ 재서명 오케스트레이션 (구현·컴파일)**: `engine.rs` `resign_app()` — 로그인→팀→인증서
   (키생성+CSR+제출+취득)→App ID→프로파일→①로 애플 인증서·프로파일 박아 재서명. **설치(④)만 빼고
   재서명 전 과정이 코드로 이어짐**. 다음: 서명된 .app을 .ipa로 재포장(설치용).
5. **④ 설치/갱신 — `idevice` 포팅 (다음, 실기기)**: LocalDevVPN 터널 경유. **㉮ `misagent`(무중단)
   먼저**, **㉯ `installation_proxy`**는 폴백/첫설치/새빌드용. **실기기 필요** — 실현성의 관건.
6. **iOS 연결 + UI**: `shard-mobile`에 C ABI feature로 엔진 노출 → xcframework, Swift 모래시계·설정·
   ㉮우선 자동 갱신. CI(macOS) 빌드 → 폰 실증.

**코드 지도(`crates/resign`)**: `main.rs`=①PoC·`auth.rs`=③+전송·`dev_api.rs`=②·`engine.rs`=⑤.

**남은 실현성 핵심 = ②③ 폰 왕복 실증 · ④ 설치 · iOS 연결** — ①검증·②③구현까지 왔다.

## 규모
포팅 방식이라 재구현보다 가벼움(그래도 통합·iOS FFI로 수 주). 엔진 결합보다 우선(사용자 지시).
**헤드리스로는 ①까지 확증됨**(실번들 재서명·검증·트림). ②③④는 Apple ID 로그인·anisette·폰
lockdownd가 필요해 **실기기(또는 anisette 서버)** 라야 실증된다 — 코드 포팅 자체는 미리 할 수
있으나 *검증*이 안 되므로, 다음 세션에서 폰 붙여 ②③④를 한 흐름으로 실증한다.
