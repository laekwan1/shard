# 배포

무엇을 어떻게 내보내는지, 그리고 **잃어버리면 안 되는 것**이 무엇인지.

## 순서 (계획)

1. **안드로이드 릴리스** — Shard 완료. Veil은 나중.
2. **iOS** — 엔진은 이식 준비됨(`shard-mobile`이 `staticlib` 내보냄). 막힌 것은
   그 위다: WKWebView는 로컬 프록시로 못 돌려서 우회가 Network Extension(VPN)
   형태여야 하고, `shouldInterceptRequest`가 없어 영상 받기가 대부분 막힌다.
   빌드에 macOS + Xcode 필수. [Shard.md](Shard.md) 참고.
3. **PC 설치배포** — 지금은 exe + 커널 드라이버(.sys)가 든 폴더 통째. 설치
   프로그램·코드 서명·자체 업데이트가 과제.

## 안드로이드 (Shard)

### 절대 잃어버리면 안 되는 것

`android/keystore/release.jks` 와 `android/keystore.properties` — **릴리스 서명
키와 비밀번호**. 이 키로 서명한 것만이 "같은 앱"으로 업데이트된다. 잃으면:

- 이미 설치한 사용자는 **영영 업데이트를 못 받는다**(새 키 = 다른 앱 = 삭제 후
  재설치, 그러면 보관함 소유권도 끊긴다 — 아래 참고).
- 남이 이 키를 손에 넣으면 **당신 앱을 사칭한 가짜 업데이트**를 서명할 수 있다.

둘 다 `.gitignore`로 저장소에서 막혀 있다. **오프라인에 따로 백업**한다.
현재 비밀번호는 `keystore.properties` 안에 있다.

### 빌드

```
android/gradlew -p android :shard:assembleRelease --offline
```

나오는 것: `android/shard/build/outputs/apk/release/shard-release.apk` —
**서명됨(v2+v3), R8로 줄이고 난독화, arm64+armv7, 약 6MB**.
이걸 `release/android/Shard/Shard.apk`로 복사해 배포한다.

에뮬레이터(x86_64)에서 확인하려면 `-Pemu`를 붙여 x86_64 슬라이스를 함께
빌드한다 — 그 산출물은 배포하지 않는다.

### 무엇이 자동으로 되나

- **버전** — `versionCode`가 git 커밋 수에서 나온다(`gitCount()`). 커밋이 하나
  늘면 코드가 하나 올라가므로, 업데이트가 폰이 "이미 그 버전"이라 여기는 일이
  절대 없다. `versionName`은 `0.1.<커밋수>`.
- **서명** — `keystore.properties`가 있으면 릴리스가 자동 서명된다. 없으면(키가
  없는 기계) 릴리스는 서명 없이 나온다 — 벽이 아니라 경고다.
- **R8** — `isMinifyEnabled = true`. 이름으로 불리는 세 경계(JNI `Native`,
  `@JavascriptInterface`, Media3)는 `proguard-rules.pro`가 지킨다. 이것을 지우면
  다운로드와 유튜브 포맷 조회가 조용히 죽는다.

### 확인한 것 (2026-08-17, R8 릴리스 빌드)

엔진 켜짐(`우회 중 1KB/s` — JNI `start`·`isRunning`·`statsJson` 동작), 보관함
영상 재생(Media3 `c2.goldfish.h264.decoder`), 크래시·`UnsatisfiedLinkError`
0건. 디버그 빌드와 동작이 동일함을 함께 확인해 R8이 아무것도 깨지 않았음을
가렸다.

### 알려진 문제 — 삭제 후 재설치하면 보관함이 빈다

앱이 미디어 권한을 받지 않으므로, 미디어 스토어는 그 폴더에서도 **이 앱이 만든
파일만** 돌려준다. 앱을 지웠다 다시 깔면 소유권 기록이 끊겨, 이전에 받은 영상·
음악이 보관함에 안 뜬다(파일 자체는 갤러리·음악 앱에서 멀쩡하다). 서명 키를
지키면 "삭제 후 재설치"가 아니라 "업데이트"가 되므로 이 문제를 피한다. 근본
해결은 미디어 읽기 권한 요청인데, 권한 팝업 하나가 늘어나는 대가가 있다 — 아직
결정하지 않았다.
