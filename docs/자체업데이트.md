# 자체 업데이트 채널 (설정 계층 2단계) — 앱스토어 없이 코드 갱신

애플이 **서명·설치 코드 자체**를 바꿔(설정 계층으로 못 덮는 층) 재서명이 깨질 때, 또는 그냥 새 기능을
배포할 때, **Veil이 최신 미서명 ipa를 호스팅하고 앱이 받아 사용자 인증서로 재서명·설치**해 코드까지
갱신한다. 앱스토어·PC 없이. 같은 번들ID로 in-place 업그레이드라 **다운로드 파일·라이브러리 등 앱 데이터는
보존**된다(만료로 앱이 죽으면 스스로 못 살아나는 부트스트랩 한계는 그대로 — 그땐 PC 1회).

## ① 앱 쪽 — **구현됨**(이 커밋)

- `state_dir/update_url.txt`에 **마커 URL** 한 줄을 두면, 앱이 실행(.active)마다 그 URL을 GET한다.
  마커 형식(두 줄):
  ```text
  <정수 버전>
  <미서명 ipa의 URL>
  ```
- 마커의 정수 버전이 앱의 `CFBundleVersion`보다 크면 → 미서명 ipa를 받아 `state_dir/work/update.ipa`에
  저장하고, **저장된 계정으로 재서명·설치**한다(`ResignModel.checkForUpdate` → `selfUpdateFromDownloaded`
  → `selfUpdate(bundlePathOverride:)`). Rust `resign_selfupdate_blocking`이 입력이 `.ipa`면 재포장을
  건너뛰고 그대로 서명한다(`engine.rs`). 완료 시 "앱을 다시 시작해 주세요" 팝업 → 확인=적용.
- **update_url.txt가 없으면 조용히 넘어간다** — ②(인프라)가 갖춰지기 전엔 아무 일도 안 한다(퇴행 없음).
- 안전: VPN 켜짐·저장 계정 필요(무인 서명), 실행 중이면 스킵. 서명·설치가 아직 도는 동안만 자체 업데이트가
  된다(파이프라인을 죽이는 애플 변경은 PC 1회 부트스트랩).

## ② 인프라 — **아직**(설정하면 켜짐)

1. **버전 박기(CI)**: `project.yml`의 `CURRENT_PROJECT_VERSION`을 빌드마다 **단조증가 값**(예: GitHub
   run number)으로 세팅. 지금은 "1" 고정이라 버전 비교가 안 된다 — 이걸 CI가 채워야 한다.
2. **Veil 업로드(CI)**: 빌드가 만든 미서명 ipa를 Veil 박스에 올리고(SSH 키 = CI 시크릿), 마커
   파일(`<버전>\n<ipa URL>`)을 갱신. anisette 서버 옆 정적 서빙이면 충분.
3. **폰 설정**: `state_dir/update_url.txt`에 그 마커 URL을 둔다(anisette_url.txt·config_url.txt와 같은 방식).

②가 갖춰지면, 새 빌드가 CI에서 나올 때마다 폰이 다음 실행에서 받아 스스로 갱신한다.

## 참고 — 애플 업데이트 대응 층 (전체 그림)

| 층 | 덮는 법 | 상태 |
|---|---|---|
| anisette(로그인) | Veil 서버 + config `anisette_url` | ✅ |
| 개발자 포털 API | config(`dev_*`) | ✅ |
| GSA 엔드포인트 | config(fork 패치 필요) | ⏸ 후순위 |
| 코드·서명·설치 | **자체 업데이트(이 문서)** | ① 완료 / ② 인프라 대기 |
| 실행 검증 사망 | — | PC(Sideloadly) 1회 부트스트랩 |
